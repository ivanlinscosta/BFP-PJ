Visão geral

Arquitetura

Todas as telas operam sobre o mesmo contrato, o AnalysisSpec, e o mesmo catálogo semântico. A IA explica e conversa; decisões e números vêm de motores determinísticos.

Cliente

React 19 + ViteTailwind v4, TanStack Query, Zustand, Recharts
CloudFrontS3 privado com OAC; /api/* para a API

API

API Gateway HTTPautorizador JWT do Cognito
Lambda Node 22Express, Zod, RBAC, logs estruturados
Lambda rebuildEventBridge diário às 06:00 UTC

Semântica e motor

Semantic Layercatálogo, validador, mesh, linhagem
Athena Query CompilerSQL parametrizado e JOIN por company_id
Customer IntelligenceDNA, sinais e NBA determinísticos

Dados

Integrações

Customer Intelligence

Pipeline sem I/O em packages/customer-intelligence, executado no rebuild local, no seed e na Lambda diária (22.447 empresas em cerca de 6 minutos na AWS).

  1. Dadosprodutos, transações, digital, CRM e jornada
  2. Featuresjanelas de 14 a 90 dias
  3. Sinais19 regras com força que decai
  4. DNA6 dimensões de 0 a 100 e tendência
  5. Elegibilidade14 ações e regras de negócio
  6. Rankingscore ponderado menos penalidades
  7. Próxima açãotop 5 e a opção de não abordar

Confiança

Governança do dado

Acesso

Lake Formation com LF-tags por domínio; usuários de negócio não veem domínios restritos, como mídia. A API lê apenas gold/*.

Qualidade e freshness

SLO e limiar de qualidade por produto em DATA_PRODUCT_CATALOG; horário de carga no SSM /bfp-pj-<env>/data-loaded-at.

Catálogo oficial

Atlan para certificação, owners e glossário; Amazon DataZone opcional.

Privacidade e versionamento

Nenhum atributo pessoal sensível em features, DNA ou NBA; dnaVersion e modelVersion em cada perfil e tabela.

AWS CDK

Infraestrutura

Ambientes independentes: bfp-pj-dev, bfp-pj-homol e bfp-pj-prod. CI em pull request; deploy em push para homol e prod via GitHub OIDC.

Data

DynamoDB (dataset, objects), bucket do lake com KMS, 10 bancos Glue, LF-tags e grants, workgroups do Athena, segredos Atlan/FullStory e SSM de freshness.

Auth

Cognito: user pool, client e grupos admin, analyst e business.

AI

Parâmetro SSM com o model id do Bedrock.

Api

Lambda da API, Lambda intelligence-rebuild (15 min) com regra EventBridge diária e HTTP API com JWT.

Web

S3 privado e CloudFront (OAC) com /api/* roteado para a API.

Observability

Dashboard CloudWatch e alarmes de erros da Lambda, 5xx da API e erros da IA.

Primeiros passos

Execução local

Pré-requisitos: Node.js 22 (20+ funciona) e npm 10+. Para AWS: AWS CLI v2 e conta com npx cdk bootstrap.

terminal
npm install
npm run seed  # gera data/dataset.json (determinístico)
npm run intelligence:rebuild  # DNA, sinais e NBA das 22.447 empresas (~50 s)
npm run dev  # web :5173 + api :3001

Abra http://localhost:5173. Em AUTH_MODE=dev os perfis de demonstração usam a senha local do README (somente AUTH_MODE=dev, nunca em nuvem):

Mariana Souzaanalyst@example.localGrowth PJ · analyst
Camila Rochaadmin@example.localClientes PJ · admin
Rafael Limabusiness@example.localOnboarding PJ · business

O workspace de demonstração (análises, 6 dashboards, favoritos e audiências) é carregado em memória ao subir a API. Desative com SEED_DEMO_WORKSPACE=false.

Deploy

deploy

npm run cognito:users  # COGNITO_USER_POOL_ID, DEMO_USER_PASSWORD, AWS_REGION

Variáveis de ambiente da API
